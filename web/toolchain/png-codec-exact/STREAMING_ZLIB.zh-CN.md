# 有界流式 zlib 适配器

English: [STREAMING_ZLIB.md](STREAMING_ZLIB.md)

`createPngCodec(...).compressZlibStream(input, { maxInputBytes, maxOutputBytes, signal?, level?: 9 })` 返回异步生成器。输入必须是普通、不可调整大小的 `Uint8Array` 块组成的异步可迭代对象，每块的完整底层 `ArrayBuffer` 不超过 1 MiB。允许该上限内的普通子视图；拒绝较大缓冲区上的单字节视图，以免跨 yield 保留过大的底层缓冲区。从大记录分块的生产者必须产出自有且有界的副本（用 `slice`，而非 `subarray`）。该约束仅适用于流式 API；现有 `compressZlib` 仍接受原来的输入形式。两个总字节预算都是必填的非负安全整数，与保持不变的整段 API 的 128 MiB 上限独立。输出块最多 1 MiB，不拼接完整输入或输出记录。

现有 `compressZlib(raw, { level: 9 })` API 及其输出字节不变。新流保留固定 zlib 1.2.13、级别 9、zlib 封装（windowBits 15）、memLevel 8 及默认策略。非空输入使用 `Z_NO_FLUSH`，最后单独传入一次空输入并使用 `Z_FINISH`，跳过空输入块。这是一条压缩流，不是多个独立压缩块的拼接。

C ABI 完全消费提供的输入，否则报错并中止；它不暴露部分消费状态。每次调用使用现有固定输入、输出缓冲区；适配器在产出前复制返回字节，最多保留一次 ABI 结果（受约 16 MiB 的 C 输出缓冲区限制）。调用方看到的块最多 1 MiB。还有待消费的输出时，生成器不会拉取下一块输入。生产者必须保持输入块不变直至下一次拉取；消费者自行负责其保留的内存。

流的生命周期内独占一个编解码器实例，其间其他 PNG 或 zlib 调用会拒绝。正常完成、消费者 `return`/`throw`、上游错误、无效块、超预算及中止信号都会释放原生流。消费者停在 yield 时，信号也立即释放它。已取消的旧生成器不能释放新流的所有权。

中止信号可打断等待上游输入。取消时即使停在 yield，也只请求一次上游 `return`。取消或已有失败时尽力清理上游：拒绝不能掩盖原始错误，清理挂起不能延迟已知失败。正常消费者 `return` 仍等待上游关闭。任意生产者可能永不结束，取消不能撤销其独立工作。没有信号时，排在未结束 `next` 后面的消费者 `return` 遵循标准异步生成器语义。调用方必须发出取消信号，而非仅丢弃迭代器。每 32 个输入块让出一个任务，避免空块或立即完成的生产者无限阻塞取消。

`createZlibStream` 是低层 ABI 测试接缝：注入的 `begin` 必须保证所有权，`push` 必须完整消费输入并返回复制后的字节，`abort` 必须释放实例。生产代码仅从固定编解码器实例取得这些操作。

## 验证

运行 `node --test web/tests/zlib-stream.test.mjs`。模拟 ABI 测试覆盖生命周期、背压、预算和取消，明确不属于 WASM 执行证据。已有本地 `dist/png_codec_native.so` 时，另一个原生检查使用固定 zlib 1.2.13，将分块调用加最后空调用与原有整段调用顺序逐字节比较，包含空输入与不可压缩输入，并用 Python zlib 独立检查解压结果。缺少该产物时明确跳过原生检查。

本次修改时本地 WASM 产物不可用。真实 WASM 执行、浏览器工作线程取消以及未来 CASC 包集成仍是独立验证门槛。未增加依赖、工具链、UI、CI 作业或已部署补充包。
