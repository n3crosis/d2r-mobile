# Remaining image recipes

Callable, source-pinned JavaScript replacements for the production `remaining-art`
and `mercenary-art` Python operation boundaries. Production routing and assembly
are documented in the [JavaScript/WASM asset runtime](../asset-runtime-js/README.md).

## API and dependencies

`createRemainingArtRecipes({ pixels, png, numeric })` returns a synchronous
`execute(operation, payload, options = {})` method. Payload is the existing
UTF-8 JSON `Uint8Array`, with base64 RGBA/header fields. Results preserve the
existing `{ width, height, files }` shape; every file is a `Uint8Array`.

Inject these independently initialized, exact backends:

- `pixels`: `createImageKernels` from `image-kernels-rust/kernels.mjs`.
- `png`: `createPngCodec` from `png-codec-exact/codec.mjs`.
- `numeric`: the existing `art-kernels/kernels.mjs` exports.

No browser canvas, system fonts, platform image decoder, or fallback encoder is
used. There is no font dependency. Original image-set, dimension, name, header,
payload-size and vault-statistics guards remain. Input validation accepts the
canonical base64 generated by the existing caller; unlike Python's decoder, it
does not accept redundant padding. Option objects are explicit, not Python-falsy
values. Neither difference affects production callers.

## Implemented production paths

- Stash: all three named backgrounds, exact strip layout, alternating mirrored
  stone extension, and the source's permitted heights.
- Advanced tabs: consumables and runes centered into the widened canvas.
- Trove: original floating-point geometry and Python ties-to-even rounding;
  numeric stone/statistics/feather kernels; exact crop, tile, line, premultiplied
  Lanczos, and masked-paste composition. `troveGeometry()` and `troveSlots()` are
  exported for the associated layout boundary.
- Vault: existing guarded numeric cover transformation and four-pixel-height
  transparent padding, including `VaultBottom.png`.
- Pouch: both permitted input widths, cap preservation and exact Lanczos center.
- Mercenary: all three original atlases, original SpA1/v61 header checks, copy
  strips and repeated self-alpha paste semantics, including
  `HirelingInventoryBG.png`.

Frontend-panel is already Python-free in `web/frontend-panel-transform.mjs`.
MainPanel block widening is already JS in `web/remaining-art-generator.mjs`.
Neither is duplicated here.

Integration must keep the existing vault orchestration: its input is the decoded
**encoded personal sprite**, after the BC3 round trip, not the pre-encoding RGBA.
Keep the caller's encoded asset hashes unchanged.

## Narrow evidence

Run from the repository root:

```sh
node web/toolchain/remaining-art-js/scripts/verify-sources.mjs
node web/toolchain/remaining-art-js/test/parity.mjs
```

The parity runner copies the already bundled Pyodide files into an isolated
temporary directory after checking their manifest SHA-256 values. It requires
Pillow 10.2.0 with its zlib 1.3.1 and compares the actual bundled Python operation
modules with the JS recipes. Inputs are deterministic synthetic decoded atlases;
no browser, game installation, download, or broad application test is involved.
The real Rust pixel WASM and existing numeric kernels are used.

Eleven cases cover all three stash variants plus a nonstandard allowed height,
both advanced tabs, trove, both pouch widths, vault padding, and mercenary.
Every output byte, output set and dimension is compared, as are trove geometry
and slots. Committed synthetic output hashes prevent unnoticed reference drift.
Source SHA-256 pins cover the native scripts, operation boundaries and numeric
backend. The runtime reports generated evidence under ignored `test-results/`.

By default **only PNG serialization is supplied by the bundled Pillow oracle**,
to isolate composition parity before the new codec is built. To verify the
complete replacement, including exact PNG bytes, build the pinned codec and run:

```sh
node web/toolchain/remaining-art-js/test/parity.mjs --wasm
```

The default comparison does not establish WASM PNG parity. Neither mode proves
browser execution or full-game/device compatibility.
