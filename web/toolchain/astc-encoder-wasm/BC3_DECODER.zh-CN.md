# 有界、原生对等的 BC3 解码器

[English](BC3_DECODER.md)

仅为独立源码基元。尚未接入 ASTC 工作线程、生产 UI、完整纹理转换或 CI。不包含游戏输入或生成的游戏数据。严格基于 `dm/tools/astc_pack.py` 的 `bc3_decode()` 与 `blocks_to_image()`；这里的对等指该原生参考实现，而非宣称与所有 BC3 解码器实现均相同。

## API 与内存

- `decodeBC3Blocks(input)` 接受固定、非共享的 Uint8Array 视图，包含完整的 16 字节 BC3 块，返回块顺序 RGBA8 Uint8Array。每块有 16 个行优先像素，每像素四字节。正确处理视图偏移，不修改或分离输入。
- `decodeBC3BlockGrid(input, { rowBlocks = 1024 })` 直接解码到行优先 RGBA8 图像，返回 `{ rgba, width, height, blockCount, rowBlocks, paddedBlocks }`。`rgba` 是新的独占 ArrayBuffer，符合现有 ASTC 基元图像契约。调用者编码时必须明确选择正确的线性或 sRGB 配置。默认复现原生 4096 像素拼接宽度；最后一行填充全零 RGBA 块。
- 两个 API 均接受 1–65,536 块：压缩输入最多 1 MiB，解码输出最多 4 MiB。网格单边最多 4096，填充后的图像必须不超过 1,048,576 像素。在分配输出前验证；本来有效的块数可能因网格填充而超限。如需分批，应由调用者在已知块边界拆分，不得截断输入。
- 直接网格路径只分配最终 RGBA 图像与 20 字节可复用调色板，不先生成完整块序 RGBA 中间数组再生成另一份图像。这是分配结构性质，不是已测量的浏览器 RSS 或速度提升。JavaScript 引擎开销与调用者保留的输入另占内存。
- 输出仍是同步、有界的。若后续需要可取消操作，应在可丢弃工作线程中调用并终止线程；本模块不自行创建线程、排队任务，也不承诺函数中途协作式取消。

## 精确解释

RGB565 端点按位复制扩展。即使颜色端点 0 小于或等于端点 1，颜色选择器也始终使用四色模式。RGB 插值采用整数向下取整 `(2*c0+c1+1)/3` 与 `(c0+2*c1+1)/3`；没有 BC1 透明色分支。

透明度端点 0 大于端点 1 时，中间条目使用原生的先 `+3` 后除以 7 的取整。否则条目 2–5 先 `+2` 后除以 5，条目 6、7 分别为 0、255。两个 24 位选择器字避免 JavaScript 对完整 48 位透明度选择器进行有损的 32 位运算。字节与选择器顺序匹配原生小端解释。不进行伽马转换、预乘、通道重排、法线重建或垂直翻转。

网格输出保留源块从左到右、从上到下的顺序。每块内像素仍为行优先。此函数不解释游戏 mip 表、物理纹理平铺、纹理尺寸、描述符或缩略图元数据。原生管线另行处理的块区域顺序及后续容器重写仍由调用者负责。

## 确定性验证

执行 `node --test bc3-decoder.test.mjs`。在已有 Python 与 NumPy 时，测试通过 Python AST 仅提取两个原生纯函数，不导入其余原生游戏工具。没有 NumPy 时显式跳过参考对照用例，不尝试安装。

使用 NumPy 2.3.5 执行：三个测试全部通过，包括 1,031 个确定性自造块与填充后原生块网格的逐字节对比。输入覆盖两种透明度模式、相同透明度端点、所有透明度与颜色选择器、反向颜色端点、24 位选择器边界与第二行网格。附加用例验证子数组偏移、不修改输入、畸形长度与类型、共享缓冲区、填充网格超限及 65,536 块的分配上限。

结果证明合成用例上的解码与拼接对等，不代表浏览器工作线程集成、完整游戏纹理对等、ASTC 质量或端到端补充包生成。
