# 有界 ASTC WASM 基元

[English](README.md)

老 GPU 选项使用的实验性编码器。其字节随公开运行时预加载，工作线程按需启动。参阅[可选运行时资源](../../runtime-build/OPTIONAL_ASSETS.zh-CN.md)。

## 来源

- 官方 [Arm astc-encoder 5.0.0](https://github.com/ARM-software/astc-encoder/releases/tag/5.0.0)，固定提交 `2ff200e08c98a61775351687ea2b5d38e455ad8b`。这是特意选择的稳定版本，不宣称为最新版本。
- [固定版本 API](https://github.com/ARM-software/astc-encoder/blob/2ff200e08c98a61775351687ea2b5d38e455ad8b/Source/astcenc.h)、[构建配置](https://github.com/ARM-software/astc-encoder/blob/2ff200e08c98a61775351687ea2b5d38e455ad8b/Source/cmake_core.cmake)、[Apache-2.0 许可证](https://github.com/ARM-software/astc-encoder/blob/2ff200e08c98a61775351687ea2b5d38e455ad8b/LICENSE.txt)。源码保留上游声明，构建时复制许可证到产物旁；未来分发必须保留。
- 原生基线：`dm/tools/astc_pack.py` 的 `encode_batch()` 使用 `-cl` 或 `-cs`、`4x4`、默认 `-thorough`、原样 RGBA，不加法线图或透明度加权标志。本基元映射到 `ASTCENC_PRF_LDR` / `ASTCENC_PRF_LDR_SRGB`、`ASTCENC_PRE_THOROUGH`、标志 0 与原样通道映射。

## 有界预设

`preset` 仅接受 `thorough`（省略时默认）或 `fast`，分别映射到 Arm `ASTCENC_PRE_THOROUGH` 与 `ASTCENC_PRE_FAST`。fast 可用图像质量换取较少编码工作，但不宣称已测量的浏览器加速。块尺寸、颜色配置、透明度处理、标志、限制及上下文生命周期均不变。ABI 版本 2 增加最后一个整数预设参数（0 thorough，1 fast），其他值拒绝。JS 包装器在分配前拒绝旧 ABI 产物，避免将 fast 请求静默编码为 thorough。模块与 WASM 必须一起重建。调用者应对纹理与描述缓存缩略图统一使用同一预设，对应原生 `--preset` 语义。

## 契约与限制

以下限制及一次性工作线程生命周期描述独立基元 API，而非[集成生成器的生命周期](../../ASTC_PRODUCER.zh-CN.md)。

`encodeAstc4x4({ rgba, width, height, profile, preset }, { signal, timeoutMs })` 接口返回原始 ASTC 块的 ArrayBuffer，而非 ASTC 文件。输入为一个独占、固定长度、紧密行优先排列的 RGBA8 ArrayBuffer。配置为默认 `linear` 或 `srgb`。RGB 值原样传递，编码解释由所选配置决定。透明度保持线性；不进行预乘、伽马转换、通道重排、垂直翻转或法线重建。输出大小为 `ceil(width/4) * ceil(height/4) * 16`，边缘不足整块时使用上游处理。

最多 1,048,576 像素，单边最多 4096，同一模块环境仅允许一个任务，编码使用单线程。限制仅描述该基元，不代表支持完整游戏纹理。输入转移后调用者缓冲区分离；失败或取消不会返还。每个结果、取消、错误或最长 120 秒期限都会终止一次性工作线程。取消无需等待同步编码主动让出。不同标签页或独立模块副本没有全局协调。

WASM 初始内存为 32 MiB，线性内存上限 128 MiB，在支持时 malloc 失败可返回错误。输入最多 4 MiB；原始输出的保守上限为 4 MiB（结合尺寸限制后的实际最大值更小）。复制一次进入 WASM，再复制紧凑结果输出。此上限不是浏览器总 RSS 上限：引擎与模块开销、转移输入、输出副本、增长与垃圾回收的临时分配不包含在内。丢弃工作线程可释放堆，但浏览器回收时机不保证。不需要文件系统、PNG 暂存、线程池或 SharedArrayBuffer。

## 有界、原生对等的 BC3 解码器

仅为独立源码基元。尚未接入 ASTC 工作线程、生产 UI、完整纹理转换或 CI。不包含游戏输入或生成的游戏数据。严格基于 `dm/tools/astc_pack.py` 的 `bc3_decode()` 与 `blocks_to_image()`；这里的对等指该原生参考实现，而非宣称与所有 BC3 解码器实现均相同。

### API 与内存

- `decodeBC3Blocks(input)` 接受固定、非共享的 Uint8Array 视图，包含完整的 16 字节 BC3 块，返回块顺序 RGBA8 Uint8Array。每块有 16 个行优先像素，每像素四字节。正确处理视图偏移，不修改或分离输入。
- `decodeBC3BlockGrid(input, { rowBlocks = 1024 })` 直接解码到行优先 RGBA8 图像，返回 `{ rgba, width, height, blockCount, rowBlocks, paddedBlocks }`。`rgba` 是新的独占 ArrayBuffer，符合现有 ASTC 基元图像契约。调用者编码时必须明确选择正确的线性或 sRGB 配置。默认复现原生 4096 像素拼接宽度；最后一行填充全零 RGBA 块。
- 两个 API 均接受 1–65,536 块：压缩输入最多 1 MiB，解码输出最多 4 MiB。网格单边最多 4096，填充后的图像必须不超过 1,048,576 像素。在分配输出前验证；本来有效的块数可能因网格填充而超限。如需分批，应由调用者在已知块边界拆分，不得截断输入。
- 直接网格路径只分配最终 RGBA 图像与 20 字节可复用调色板，不先生成完整块序 RGBA 中间数组再生成另一份图像。这是分配结构性质，不是已测量的浏览器 RSS 或速度提升。JavaScript 引擎开销与调用者保留的输入另占内存。
- 输出仍是同步、有界的。若后续需要可取消操作，应在可丢弃工作线程中调用并终止线程；本模块不自行创建线程、排队任务，也不承诺函数中途协作式取消。

### 精确解释

RGB565 端点按位复制扩展。即使颜色端点 0 小于或等于端点 1，颜色选择器也始终使用四色模式。RGB 插值采用整数向下取整 `(2*c0+c1+1)/3` 与 `(c0+2*c1+1)/3`；没有 BC1 透明色分支。

透明度端点 0 大于端点 1 时，中间条目使用原生的先 `+3` 后除以 7 的取整。否则条目 2–5 先 `+2` 后除以 5，条目 6、7 分别为 0、255。两个 24 位选择器字避免 JavaScript 对完整 48 位透明度选择器进行有损的 32 位运算。字节与选择器顺序匹配原生小端解释。不进行伽马转换、预乘、通道重排、法线重建或垂直翻转。

网格输出保留源块从左到右、从上到下的顺序。每块内像素仍为行优先。此函数不解释游戏 mip 表、物理纹理平铺、纹理尺寸、描述符或缩略图元数据。原生管线另行处理的块区域顺序及后续容器重写仍由调用者负责。

### 确定性验证

执行 `node --test bc3-decoder.test.mjs`。在已有 Python 与 NumPy 时，测试通过 Python AST 仅提取两个原生纯函数，不导入其余原生游戏工具。没有 NumPy 时显式跳过参考对照用例，不尝试安装。

使用 NumPy 2.3.5 执行：三个测试全部通过，包括 1,031 个确定性自造块与填充后原生块网格的逐字节对比。输入覆盖两种透明度模式、相同透明度端点、所有透明度与颜色选择器、反向颜色端点、24 位选择器边界与第二行网格。附加用例验证子数组偏移、不修改输入、畸形长度与类型、共享缓冲区、填充网格超限及 65,536 块的分配上限。

结果证明合成用例上的解码与拼接对等，不代表浏览器工作线程集成、完整游戏纹理对等、ASTC 质量或端到端补充包生成。

## 有界 BC3 到 ASTC 批处理编排

隔离、未集成的源码基元。它组合已有的有界 BC3 解码器与 ASTC 工作线程客户端；真实浏览器 WASM 转码仍未验证。测试明确注入模拟编码器，不是 Arm ASTC 编码。不涉及生产 UI、CI、游戏文件、纹理元数据重写或补充包写入。

### 契约

`transcodeBC3Batches(source, { profile, signal, batchBlocks = 65536, encode })` 是惰性异步生成器。`source.size` 必须是非负安全整数且为 16 的倍数。零字节不产出结果。`source.readAt(offset, length, { signal })` 必须返回或异步解析为长度准确、固定、非共享的 Uint8Array 视图。短读或超长读取均失败；生成器不重试，也不静默截断。配置必须明确为 `linear` 或 `srgb`。`encode` 默认为 `encodeAstc4x4`；覆盖它仅是依赖注入入口，不代表另一个已验证的编码器。

每个产出项包含 `blocks`（原始 ASTC 块的 Uint8Array）、`blockOffset`、`blockCount`、`completedBlocks`、`totalBlocks` 与 `profile`。偏移和计数以块为单位，而非字节。完成计数在编码成功后增长，仅在生成器完整消费并成功时达到总数。计数是供调用者使用的进度信息，不是持久化事务记录。

一次仅等待一个读取与一个编码。只有消费者请求下一项才读取下一批；没有预取队列。批量为 1–65,536 块，压缩输入与产出 ASTC 均最多 1 MiB。解码器默认每行 1024 块，含末行填充的 RGBA 最多 4 MiB。裁剪前验证带填充 ASTC 长度。只移除尾部零网格填充；不重排或裁掉真实源块。读取字节偏移严格递增。

消费者应写入或消费每个产出块并释放后再前进；收集全部块会主动保留整个输出，失去流式优势。此模块不保留完整纹理或补充包，不写入输出，也不在后续批次失败时回滚。部分输出清理由调用者负责。RGBA 转移到真实工作线程会消耗该中间缓冲区；源输入不被分离或修改。最后一个不完整网格可能短暂同时保留带填充编码输出与紧凑前缀副本。浏览器或模块开销、来源缓存与延迟垃圾回收另占内存，不包含在缓冲区上限内。

### 取消与限制

在开始工作、读取后与编码后检查 AbortSignal，并将其传入来源与编码器。即使注入的操作忽略信号，对读取或编码的等待也可取消，但底层来源仅在遵守信号时才能释放自己的待完成 I/O 资源。真实编码器客户端会终止可丢弃工作线程。自定义编码器若忽略取消，生成器不能强制停止它。同步解码虽有界，但不在函数中途协作式中断。在产出结果处暂停时调用 `return()` 或跳出迭代会阻止后续读取；取消已进行的操作应使用信号。

调用者取消或提前停止时，不得将之前的块视为完整纹理。此模块不解释纹理尺寸、mip 边界、块线性平铺、描述缓存、缩略图或 CASC 布局。它不是完整原生 `astc_pack.py` 流程；BC3 解码源码对等不证明真实 BC3 到 ASTC 转码对等。

### 验证

`node --test bc3-astc-batches.test.mjs` 的四个确定性模拟编码器测试通过。覆盖惰性顺序处理、65,536 块加三块填充尾批、有界输出、单调计数、准确裁剪尾部、畸形长度与配置、短读、错误编码长度、空输入、读取和编码前后及过程中的取消、消费者停止，以及三批间已解码源块身份的保留。真实 WASM 编译、浏览器执行、编码质量与原生及浏览器块对等仍待验证。

## 有界纹理容器流式适配器

仅为隔离源码，未接入生产。`texture-stream.mjs` 按 `dm/tools/astc_pack.py` 的结构解释包装 `bc3-astc-batches.mjs`：格式字节位于偏移 4，无符号小端相对数据指针位于偏移 40，`dataStart = 40 + pointer`。BC3 格式 0x3d 映射为 ASTC 0x5f，采用线性编码；0x3e 映射为 0x51，采用 sRGB 编码。其余头部字节逐字节保留。负载仍为每块 16 字节，因此输出文件长度和偏移不变。

### 流契约

`transcodeTextureStream(source, { signal, batchBlocks, encode })` 消费具有非负安全整数 `size` 的 readAt 来源。`readAt(offset, length, { signal })` 必须返回长度准确、固定、非共享的 Uint8Array。它产出分类事件：

- `skip`：少于 48 字节时原因为 `short-input`；不支持的格式为 `unsupported-format`，附带观察到的数字格式码。这些情况不产出字节或完成事件。跳过是明确的，不会静默重写不支持的文件。
- `header`：独占字节块与绝对输出偏移。首个事件还报告原格式、新格式、dataStart 与配置。仅修改字节 4。首读为 48 字节，随后头部块最多 64 KiB。即使头部异常长，也流式处理而不完整保留。
- `blocks`：原始 ASTC 字节块、绝对输出偏移、块数、已完成块数与总块数。使用现有顺序有界批处理适配器，每块数据最多 1 MiB。编码配置由原格式决定，不猜测，也不让调用者覆盖。
- `complete`：仅在全部头部与负载字节成功产出后发出，包含不变的文件大小与格式、配置。它不代表下游文件写入器已持久化输出。

消费者必须区分事件类别、及时消费字节块，并明确处理跳过。适配器不写入，不保留完整纹理或 CASC 包。错误、取消或提前终止后的部分输出清理由消费者负责。保留全部产出块会主动失去流式优势。头部块复制后输出，避免保留巨大的来源底层缓冲区；来源缓存与 JavaScript 垃圾回收不受适配器控制。

### 边界、取消与原生差异

支持的格式必须满足：数据起点至少为 48、严格小于来源大小，且剩余非空尾部可被 16 整除。拒绝 dataStart 小于 48 是有意加强的畸形输入验证；原生脚本未显式拒绝与头部重叠。格式映射、指针解释、未修改头部字节与块顺序遵循原生结构规则，但不证明完整原生转换对等。

在首个输出前检查可预见的批处理选项错误。短读、错误缓冲区类型、共享或可变长缓冲区、不安全大小和畸形偏移均失败。调用者读取函数或注入编码器的错误替换为固定类别信息，不包含私有文件名或原始原因。取消错误保留通用 AbortError 类别。

取消信号传入头部读取与批处理适配器，在块间检查，也停止等待未完成读取。底层读取仅在来源遵守信号时释放资源。同步有界解码不协作式中途打断。在产出块处跳出可阻止后续读取；中断已进行工作需要 AbortSignal。流未完成时，之前的字节块不构成完整有效转换。

这里不实现 mip 表解析、纹理尺寸解释、描述缓存更新、缩略图变化、CASC 写入、质量报告或游戏内容处理。原生脚本中独立的容器与包职责仍待完成。

### 合成证据

`node --test texture-stream.test.mjs` 的五个确定性测试通过，使用注入模拟编码器而非真实 ASTC 压缩。用例覆盖两种格式与配置映射、准确头部保留、顺序批次偏移和计数、有界长头部读取、惰性提前停止、显式跳过、重叠或超界或未对齐指针、短读、无效大小与选项、待完成读取取消及保护隐私的错误类别。不宣称真实 WASM 转码、游戏文件行为或完整原生管线对等。

所有载荷范围必须位于完整表之后且在缩略图之内，长度须为非零的16字节倍数。
转换顺序由表顺序决定，不由物理范围顺序决定。文件头、表、空隙、尾部以及
所有其他非载荷字节逐字节保持原样，不改写指针。

第一次编码调用之前检查所有选中的元数据与布局。随后至多保留一张解码后的
缩略图，对每级串行调用现有 `transcodeBC3Batches`。有界来源是该缩略图的视图，
不是整包缓冲区。不修改输入描述字节。失败或取消后不返回部分 JSON 输出。
错误只含固定代码（`ASTC_DESCRIPTOR_INVALID`、`ASTC_DESCRIPTOR_TRANSCODE`）
或固定 AbortError，不包含文件名、解析器详情或注入编码器的文本。
底层编码器仍负责取消与释放自己的资源。

### 有意收窄的接受范围

- UTF-8 JSON 数组，输入最多16MiB，输出32MiB，条目与映射键各最多100,000个。
- 每张缩略图最多4MiB，1–64个非空 mip，载荷范围不重叠。
- 表从字节8或以后开始；有符号指针不能到达元数据或超出缩略图。
  支持空隙与逆向物理顺序。
- 只接受规范填充的 base64，不接受空白或不同的填充位。
- Map 键为1–1024字符的小写可打印 ASCII；记录文件名为最多1024字符的字符串。
  匹配前将记录名称转为小写。
- 元数据遍历最多500,000节点及64层。拒绝非有限数及超出 JavaScript 安全范围的
  整数，而不是在序列化时损坏元数据。缩略图字段只允许字符串、null 或缺失。
- 批量限制沿用 `transcodeBC3Batches`（最多65,536块）。

原生先按 sRGB 合并所有缩略图再编码。本实现为控制内存而串行处理 mip 与条目。
已覆盖描述布局及保留行为，但不声称改变分组后生成的 ASTC 字节与原生相同。
真实编码器、完整缓存、图像保真度、完整补充包、设备及游戏行为的一致性尚未证明。
未启用运行时、界面或 CI 集成。

### 定向验证

`node --test web/toolchain/astc-encoder-wasm/descriptor-cache.test.mjs`
只使用手写 JSON、缩略图与注入的模拟编码器。覆盖格式映射、sRGB 不匹配、
串行调用、元数据保留、相对指针/计数/大小/重叠拒绝、逆向物理 mip 顺序、
非载荷字节不变、输入不变、base64/预算失败、错误清理以及挂起编码器的取消。
夹具不包含游戏文件或游戏文件名。

## 真实 WASM 编码冒烟测试框架

在 `bash build.sh` 生成隔离的 `dist/` 产物后，使用 Node 24 或更新版本执行 `node wasm-smoke.mjs`。这是仅供测试的 Node worker_threads 框架，不是生产浏览器工作线程或已部署运行时。不修改构建环境标志。

框架要求存在生成的模块、WASM 二进制、准确的 Arm 提交记录与 Emscripten 4.0.20 版本记录。读取前限制每个产物最多 32 MiB。它动态导入真实生成模块，通过 Emscripten 的 `wasmBinary` 工厂选项提供准确的本地 WASM 字节。Node 测试线程明确提供 `self` 与 `WorkerGlobalScope` 垫片；fetch 和 XMLHttpRequest 调用直接抛错，不进行网络加载。这是测试适配，不证明原生浏览器工作线程兼容性。

32 个微小确定性输入覆盖 thorough/fast 预设、线性与 sRGB 配置、1×1、4×4、5×7、17×3 尺寸，以及不透明红色与 RGBA 渐变。每个输入经真实 WASM C ABI 编码两次，检查确定性；thorough 输入额外省略预设编码，验证默认字节不变（共 80 次编码）。检查 ABI 版本 2、导出可用性、输出长度、非零数据、不同输入输出区别，以及无效尺寸、配置、预设、长度与空指针。现有 `encodeWithModule` 包装器负责分配清理。没有 WASM 解码导出，因此不断言解码质量或原生字节对等。

唯一工作线程在成功、失败或父线程 30 秒期限到达时均被终止。缺失产物、测试失败、线程意外退出或超时均使父线程返回非零；缺失产物不被静默跳过。JSON 成功记录明确测试专用垫片 Node 环境、输入结果、产物哈希与观测到的最大堆长度。微小输入上的堆长度在配置范围内，不验证最大内存限制的强制执行，也不验证进程或浏览器总 RSS。Node JavaScript 堆资源限制也不限制 WebAssembly 线性内存。
