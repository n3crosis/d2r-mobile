# Remaining production image boundary

Scope: `asset-generation-spike/src` and its generated, source-pinned production modules, plus the embedded overlay recipe. Development screenshot/check scripts and tvOS/iOS offline tools are not browser payload requirements. `original_bc3.py` and `bounded_encoder.py` remaining in the generation directory are not evidence that the migrated production BC3 path still needs Python.

Only PNG is required by these production image boundaries. Sprite v31 is raw RGBA; v61 deswizzle/BC3 decode is already supplied outside Pillow. There is no production requirement here for JPEG, TIFF, WebP, GIF or DDS support. The close-button image is source-packaged, not regenerated by this browser recipe, so its offline supersampled arbitrary-width line routine does not need porting. Mac keyboard glyph generation is excluded because browser overlay forces the Switch/iOS path and removes `DM_OVERLAY_MAC`.

Font inputs are provided from the user's game archive, not downloadable assets:

- `blizzardglobal-v5_81.ttf` (`BlizzardGlobal-V5_81.ttf` at map-goal archive lookup).
- `exocetblizzardot-medium.otf`.
- BASIC layout, not RAQM/HarfBuzz. Current backend is FreeType **2.6.0**.
- HUD uses `getlength`, `getmetrics`, `textbbox`, alpha masks, grayscale antialiasing, fill and strokes of width 1/2; anchors `ls`, `mb`, plus default `la`.
- Map labels use size 48, `textlength`, anchor `mm`, and Chinese/English/Spanish/Mexican-Spanish/Russian strings. HUD uses Exocet size 220 for difficulty digits; BlizzardGlobal sizes include 26/30/34.
- Preserve 26.6 advances, kerning/load flags, bbox/anchor rounding, stroke placement and direct text drawing semantics. Text alpha composition must match `ImageDraw.text`; it must not be assumed equivalent to generic source-over.

## Practical replacement architecture

1. Keep the existing bounded JS numeric kernels. Route image buffers into this small Rust module; translate image recipe control flow into JS. Add only the two used shape operations: inclusive integer rectangle border and clipped horizontal line. Do not build a Pillow compatibility framework.
2. Add a small PNG module preserving **encoded bytes**, not merely pixels. Keep all original guards. This lets native-art, mercenary, basic image-default-frame, vault, and eventually the non-font remaining art leave Pyodide first.
3. Add a scoped FreeType wrapper compiled from the **exact existing 2.6.0 Emscripten port sources/configuration**, with the used Pillow `_imagingft.c` algorithms extracted from CPython argument handling. A C ABI can be called by JS or a Rust orchestration shim; “Rust/WASM” does not require rewriting FreeType. Reuse the already source-pinned `test/build-hud-reference.py` FreeType source recipe and audited source digest.
4. Translate HUD/map-goal recipes and compare all generated dimensions, metrics, pixels and encoded output hashes against the source-pinned oracle. Then remove Python modules from runtime closure and finally delete the Pyodide/Pillow payload. No `.NET` changes are required.

Canvas, browser image decode/encode, `fontdue`, `rusttype`, or default `image`-crate resampling are not substitutes for exact legacy pixels. A fresh font rasterizer or FreeType upgrade may be an intentional future change, but is not this compatibility-preserving payload migration.

## PNG implementation, without weakening hashes

Critical guard: `native_art_original.py` (source `dm/ios/tools/native_art/generate.py`) compares SHA-256 of **entire encoded PNGs** with `native_art_manifest.json`. `hud.py` rechecks those byte hashes. A valid PNG from a standard Rust encoder can be visually identical yet fail these guards.

Use the pinned Pillow 10.2.0 paths:

- `PngImagePlugin._save`: supported RGBA mode, IHDR fields, chunk order, no extra metadata, IDAT chunking and IEND.
- `ZipEncode.c`: per-row filter selection and tie-breaking, compressor parameters, row order and streaming flush boundaries.
- Exact **zlib 1.3.1**, which is the bundled Pillow-linked zlib. Do not accidentally select Python's separately linked zlib 1.2.13. Do not assume miniz, fflate, pako, zlib-rs or zlib-ng produce identical deflate bytes.

The conservative next implementable step is a source-pinned, build-only C-to-WASM build of zlib 1.3.1 with a narrow bounded ABI, plus a direct row-filter/chunk writer port. Link only deflate/inflate/checksum code, no Python, no Emscripten filesystem/runtime, no arbitrary codec framework. Build tooling is not part of the user download. This environment currently has Rust/wasm-ld and a host C compiler, but no installed C-to-WASM clang/emcc; provision an official build toolchain before claiming the codec artifact exists.

For the decoder, restrict to the authenticated PNG forms actually produced/packaged: bounded RGBA8 plus verified fixed close-button input. Reject excess dimensions, oversized decompression, invalid CRCs, unsupported color/depth/interlace, and trailing malformed chunks rather than silently routing through browser decoders. Confirm the close-button's IHDR before narrowing the final decoder contract.

Do not change encoded PNG hash guards or replace them with pixel digests as part of this work. Add narrow byte-for-byte fixtures for row-filter ties, all PNG filters, transparent pixels, IDAT boundaries and representative production dimensions against **the bundled Pyodide Pillow encoder**, then check frozen production asset hashes when authenticated inputs are available. Native Pillow 10.2 with another zlib build is insufficient as the PNG-byte oracle.
