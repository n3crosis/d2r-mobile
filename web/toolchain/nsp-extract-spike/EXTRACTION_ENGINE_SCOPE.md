# Local extraction Worker protocol

This is an internal extraction adapter boundary, not UI enablement or a complete NSP-to-IPA claim. The initial engine/Worker tests passed [run 39399152791](https://github.com/n3crosis/d2r-mobile/actions/runs/39399152791), commit `b90743b5b70fdf9ffa895dfd1d54a0201ad270c7`. The next integration batch additionally exercises the real main-thread client in Chromium with clean disposal and invalid-input sanitized rejection, plus focused client/adapter Node tests; that added coverage awaits CI. Earlier native BKTR build/crypto/routing/integrity smoke passed [run 39398141322](https://github.com/n3crosis/d2r-mobile/actions/runs/39398141322), commit `44b8e64d550f3575e88ebf83f65bdcfb9673b6c5`. Valid signed game base/update fixtures have not been tested.

`extraction-worker.mjs` statically imports the pinned WASM module, its boundary and the pure engine. No arbitrary source URL, native name, filesystem path or callback may be provided by a message. Input is `{id,operation,payload}` with a monotonically increasing positive safe-integer ID. Exactly one request may be outstanding; callers must await its result before sending another. Success is `{id,ok:true,result}`; failures use `{id,ok:false,error:CODE}` with a fixed allowlist in `extraction-errors.mjs`, never native/parser text. During initialization only, `{id,progress:{stage,completed,total,bytes}}` reports fixed substages and bounded numeric counts, never selected filenames, key names/values or rights IDs. These events cannot renew the request deadline. Operation errors close the session. Invalid envelope/busy messages are rejected without adding work to an unbounded queue. Cancellation during synchronous hashing must terminate the Worker; do not wait for a cancellation RPC to run.

Operations:

- `initialize({nsps: Blob[],prodKeys: Blob,titleKeys?: Blob})` reads bounded key bytes inside the Worker (an absent title file becomes an empty memory-only input), wipes temporary arrays, uses the production NSP outer-catalog validator, computes every full-NCA SHA256 independently, verifies headers and opens authenticated Meta content before parsing CNMT. Returns `{records,inventory}`. Duplicate content IDs with different measured identity reject; identical duplicates are collapsed. NCZ and malformed NCA names reject. Other ordinary ticket/certificate members are not extracted.
- `select({options})` runs the known D2R expansion policy on retained authenticated records and independently measured inventory, preserving all generic metadata resolver checks. Only `baseVersion`, `patchVersion`, `dlcVersions` options are accepted. It requires the exact D2R application, associated update and known Warlock add-on identities, with the conservative single nonempty Data content at ID offset zero and attributes zero. The add-on remains in required contents and must have both its independently verified full NCA hash/size and an actually signature-verified NCA Data header. Missing/unknown DLC, inconsistent content types and unsupported layouts reject. It currently supports exactly one Program at ID offset zero in each selected base/patch. The known unlock-only add-on is not overlaid onto Program RomFS; no caller ownership Boolean or native-runtime change is introduced. This is local package-input evidence, not legal ownership, purchase or ticket-entitlement verification. Real DLC layout compatibility remains unproven until authenticated packages are supplied. Returns canonical `{selection,token,entries}`, where entries are `{index,name,size,offset}` for the independently verified selected ExeFS. This does not establish executable-version compatibility.
- `readExefs({token,index,offset,count})` returns a transferred Uint8Array, capped at 64 KiB with exact BigInt range checks. Capture/stage required executable members before opening RomFS. Version allowlisting and executable conversion remain separate required steps.
- `openRomfs({token})` opens the authenticated base or supported base/patch merge, revokes the ExeFS token and returns `{token,size}` for the final authenticated RomFS level.
- `readRomfs({token,offset,count})` returns at most 64 KiB. This can back `indexRomfs` and then `createCascLogicalAssets` through a bounded serial RPC client. Generators must receive only this read capability, never the Worker, key/input handles, arbitrary execute function or session controls.
- `dispose({})` wipes native state, drops retained metadata, acknowledges and closes the Worker. The owner must also terminate it on failure, cancellation, timeout, malformed response or disposal failure. There is no resumed-session or persistence path.

The existing coordinator default disposes before generation. Lazy RomFS readers require the separately reviewed opt-in archive-lifetime mode: retain the isolated Worker only through entry streaming, then dispose before final validation/commit and on every failure. No full decrypted RomFS staging is required by this engine. ExeFS and RomFS share one native active context, so opening RomFS makes all previous ExeFS capabilities unusable. The caller must stage only the small required executable subset first, or introduce another independently reviewed context design; concurrent open switching is not supported.

Node tests use an explicitly fake native boundary to test catalog/selection orchestration, key-array wiping, hashes, states, stale tokens and bounds. They are not positive NCA proof. Chromium smoke instantiates the real Worker/module and checks forbidden-operation sanitized failure plus clean disposal; production signature gates remain unchanged. Worker isolation/CSP, local staging and the parent RPC capability wrapper still need integration review before enabling UI generation. Same-origin code is trusted; JavaScript cannot prove complete secret erasure after crashes or browser memory copies.

The expansion-policy integration tests use synthetic CNMT for the known IDs and mock native verification. They assert that missing Meta evidence, wrong whole-DLC hash, unsigned DLC headers and a non-Data NCA header reject, and that the DLC remains in requiredContents without an ownership flag. The generic content-selection parser/resolver remains independently reusable; there is no production worker fallback that omits the known DLC requirement.
