# 浏览器本地 zsign 源码构建

简体中文 | [English](README.md)

此可选工具链复用
[用户指定版本的 lbr77/zsign-wasm](https://github.com/lbr77/zsign-wasm/tree/0fb14887c61716508088e365447ffdedf7a1837d)
中的浏览器移植设计和应用包 ABI，签名实现采用
[zhlynn/zsign v1.1.3](https://github.com/zhlynn/zsign/releases/tag/v1.1.3)。
它**不是**对旧分支已提交 WASM 二进制文件的逐字节重建。
所有源码和编译器版本均固定在 `pins.json` 中。

## 为什么采用源码派生适配

指定分支已有浏览器桥接层和可移植文件映射。根据 GitHub 文件树元数据，
其已提交 WASM 为 2,425,871 字节，但外部预编译 OpenSSL 依赖没有固定版本。
这不是本次新构建的体积测量值。该分支的原生签名基础早于当前上游修复，
包括拒绝不可读取的资源，而不是错误地将其作为空文件生成签名记录。

本工具链保留分支的 C 应用包 ABI，并适配当前上游。资源哈希改为每次读取
64 KiB 的 OpenSSL EVP 增量计算；可修改文件采用带边界和错误检查的
`fopen`、`fread`、`fwrite` 映射，不使用 `mmap`。生成的运行时禁用动态执行。
不包含 JSZip 封装、`new Function`、下载运行时代码、WWDR 下载助手、原生命令行、
安装器、元数据提取器、OCSP 客户端、归档编解码器或 WASI 兼容垫片。
不依赖 TLS 或 libssl。

## 构建

需另行准备 Git、Python 3、Perl、Make 以及项目固定的 Emscripten 4.0.20。
从仓库根目录执行：

    bash web/toolchain/zsign-wasm/build.sh
    node web/toolchain/zsign-wasm/wasm-smoke.mjs

构建脚本获取精确源码提交，在源码副本上应用已审核补丁，使用 Emscripten
编译官方 OpenSSL 3.5.9，并仅链接 libcrypto。脚本不会安装软件、运行下载的
预编译程序、接收凭据或签名应用。`no-module` 保留旧版 P12 加密需要的静态
legacy 提供程序，不得替换为 `no-legacy`。签名调用要求 default、legacy
提供程序及密码学随机源均已初始化；失败返回 `-205`，不会下载提供程序或使用弱随机数。

输出包括 `dist/zsign.mjs`、`dist/zsign.wasm`、三个许可证文件、OpenSSL 声明文件、
固定版本清单、编译器版本、补丁凭据和构建凭据。构建凭据记录输出文件的字节数
及 SHA-256，不代表浏览器执行、可安装性、证书有效性或设备验证。
部署时必须同时保留：

- `ZSIGN-LICENSE.txt`：上游 MIT，版权声明为 2026 zhlynn。
- `PORT-LICENSE.txt`：指定分支提供的 MIT，版权声明为 2023 DeepSeek，原样保留。
- `OPENSSL-LICENSE.txt`：OpenSSL Apache-2.0，同时保留 `OPENSSL-NOTICE.txt`。

## 工作线程 ABI 与隔离

`zsign.mjs` 默认导出模块化工厂。必须通过应用的封闭字节工厂提供已验证的 WASM
字节，不允许 URL 回退加载。原生导出仅有 `_zsign_sign_bundle`、`_malloc`、
`_free`。运行时提供 `FS`、`MEMFS`、`HEAPU8`、`ccall`、`UTF8ToString`。
工作线程直接调用固定函数，不接受调用方指定的导出名；模块标准输出和错误输出必须静默。

`zsign_sign_bundle` 接收九个 UTF-8 C 字符串和五个整数：

    input_folder, cert_file, pkey_file, prov_file, password,
    entitlements_file, bundle_id, bundle_version, display_name,
    adhoc, sha256_only, force_sign, weak_inject, enable_cache

由构建控制的工作线程必须使用固定内部路径和空可选参数：
`/work/Payload/App.app`、空证书路径、`/credentials/identity.p12`、
`/credentials/profile.mobileprovision`、密码、四个空可选字符串，
以及 `0, 1, 1, 0, 0`。原生调用前必须拒绝任意路径、应用标识修改、自定义权限、
缓存或调试选项、ad-hoc 签名请求和包含扩展的应用。

返回码：`0` 成功；`-201` 文件树无效；`-202` 缺少凭据路径；`-203` 身份或描述文件
初始化失败；`-204` 签名失败；`-205` 密码提供程序或随机源不可用；
`-206` 描述文件与应用的兼容性检查未通过。
必须将其转换为固定的 UI 错误码，不能显示原生错误、证书名称、密码或文件内容。

每个任务使用全新的工作线程和模块。显式分配每个字符串，使用后清零并释放。
无论成功、失败、超时还是取消，都要清理凭据文件与缓冲区、清零模块堆并终止工作线程。
浏览器字符串无法可靠擦除，因此不能承诺取证级清除。凭据不得进入持久化存储、
日志、遥测、工作线程启动资产或网络请求。签名输出有意嵌入描述文件，
但绝不包含 P12 或密码。

## 内存与输出契约

- 资源哈希每次最多读取 64 KiB，适用于多 GB 文件。
- 每个原生可修改文件映射最多 128 MiB。
- WASM 线性内存初始为 32 MiB，上限为 512 MiB。
- 文件系统适配器必须另外将可修改文件总量限制为 256 MiB，并限制条目数、
  路径长度和元数据。WASM 堆限制不等于 JavaScript 分配限制；Mach-O 可能同时
  存在于文件系统与原生临时内存中。
- 资源使用不可变 Blob 切片，在专用工作线程中同步读取。不得将整个 IPA
  或资源文件树复制到 MEMFS。
- 使用现有有界 ZIP 写入器输出修改后的 Mach-O、CodeResources、
  embedded.mobileprovision 以及未修改资源，保留原应用文件夹名称。
- 已完成的未签名 IPA 保持不变。签名是独立事务，只有完整归档验证成功后才发布
  签名结果；失败或取消仍保留未签名下载。

## 离线描述文件兼容性

身份初始化后，桥接层从固定的 `Info.plist` 路径读取未修改的根应用
`CFBundleIdentifier`，检查读取错误并限制为 1 MiB。兼容性门禁将 CMS
原始字节及提取内容分别限制为 4 MiB，检查所选证书是否在描述文件中、
证书和描述文件日期是否符合设备时钟、证书 OU 与团队是否一致，以及应用
标识前缀是否匹配。旧版应用标识前缀不必等于团队 ID。
仅替换派生授权，原始描述文件字节保持不变。

该门禁有意仅接受 XML 格式的描述文件内容。二进制描述文件、XML 注释或
CDATA、重复或非标准日期节点（必须为 `YYYY-MM-DDTHH:MM:SSZ`）、
不明确的团队或证书 OU，以及不支持的通配符均会被拒绝。应用标识仅支持
精确匹配或完整末尾 `*` 段。匹配的钥匙串组通配符展开为具体应用标识；
描述文件明确授权的具体共享组保持不变。不支持的描述文件仍可回退下载未签名 IPA。
完成上述支持的展开后，授权字符串中剩余的任何通配符（包括 iCloud 授权）
均会被拒绝；遍历最多 16 层、4,096 个节点。这类描述文件可能适用于 Apple
工具，只是当前实现不支持；桥接层不会推断容器、应用组或 iCloud 能力。

既有应用标识上限为 255 字符，包括描述文件前缀和分隔点，不只是包标识。
已验证的前缀加包标识超过上限时返回 `-207` / `SIGNING_APPLICATION_ID_TOO_LONG`，
区别于描述文件不匹配（`-206`）。精确/通配符匹配与所有长度上限保持不变。
源码检查和模拟原生状态不执行此新返回路径；运行时交付前须在 CI 重建签名器。

这些检查不验证 CMS 的 Apple 签名、信任链、撤销状态、设备资格、应用所需
能力或实际可安装性。

## 验证边界

补丁转换器已针对精确引用的源码文件运行，Python 和 Shell 语法检查已通过。
此处尚未完成 WASM 编译、真实凭据使用、浏览器签名或设备安装。
构建后的 Node 24+ 冒烟检查不使用凭据，用于验证离线实例化、运行时导出、
构建凭据哈希及静态密码提供程序和随机源初始化。

启用 UI 前，CI 还必须验证新旧 P12 解析、不可读取或短读资源拒绝、签名后的
Mach-O 与资源完整性，以及工作线程的离线清理。原生签名返回成功本身不代表
Apple 信任、权限或描述文件与设备资格、撤销状态或可安装性。
