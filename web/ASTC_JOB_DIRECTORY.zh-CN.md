# 父级持有的 ASTC 作业目录

English: [ASTC_JOB_DIRECTORY.md](ASTC_JOB_DIRECTORY.md)

`createAstcJobDirectory({ root, signal, stopAndDrain, cleanupTimeoutMs })` 在调用方
提供的 OPFS 目录中创建全新 UUID 子目录。返回冻结租约，含 `root`、`dispose()`
和 `status`。父级保留租约，只把子目录句柄克隆给生产线程。不涉及源目录、游戏、
网络或 UI。默认有界等待 1000 ms，可显式指定 1–30000 ms。`randomUUID` 是测试
注入接口；生产默认使用加密随机 `crypto.randomUUID()`。

成功产包后，在最终 File 的整个导出/读取生命周期保留租约。收到 File 不意味着
可以删除其底层目录。导出完成或放弃后，先终止/撤销生产线程，再等待 `dispose()`。
释放被拒绝时必须保留租约供重试。取消所传 signal 会启动尽力清理；所有者仍须
观察 `dispose()` 才能确定结果。

可选、受信任的 `stopAndDrain` 在任何删除前执行。它应终止生产线程、撤销源 RPC、
移除监听器并等待受跟踪操作。如果未提供，所有者须在释放前自行完成这些步骤。
回调失败会阻止删除并允许重试，因此必须幂等；尚在等待的回调会共享，不会重复
调用。Worker 的 `terminate()` 没有完成 Promise，也不能证明原生文件写入已排空。
锁定/延迟的文件系统操作仍是可观察错误或待清理状态，不可声称清理成功。真实
浏览器行为仍需浏览器测试。

删除前通过 `isSameEntry` 与原始子目录句柄比较。预先存在的名字和已知替换项
绝不删除；已消失的自有目录视为已释放。OPFS 既不支持独占目录创建，也不支持
按句柄匹配原子删除；存在性/身份检查无法防御恶意同源代码在检查与修改间的竞态。
此租约要求同源代码可信且协作，不构成针对它的安全边界。不回退删除未知条目。

超时不会取消文件系统操作，也不代表它未执行。原始获取/删除继续受跟踪，多次
`dispose()` 等待同一待清理操作，不并发发起删除。已结束的失败之后，下一次释放
会重新检查所有权。`status` 返回 `{ phase, removed, cleanupPending, lastError }`；
只有成功清理才进入 `disposed`。创建失败或超时抛出的错误保留 `error.lease`，
包括目录句柄仍在迟到获取的情况。自动启动清理，但父级须保留租约以观察或重试。

`node --test web/tests/astc-job-directory.test.mjs` 用合成句柄测试所有权、替换
拒绝、停机顺序、超时单一操作、迟到获取清理、取消和重试。这些测试不证明真实
OPFS 锁、跨线程完成或设备行为。
