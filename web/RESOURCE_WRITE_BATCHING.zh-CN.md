# 有界资源写入合并

[English](RESOURCE_WRITE_BATCHING.md)

原始资源和 Legacy Device Pack 导出的认证读取及 RPC 上限保持 64 KiB。仅文件系统写入上限改变：使用一个按需分配、固定 1 MiB 的缓冲区，将顺序读取合并成串行写入。不提供可配置增长、并发写入、新界面选项，不增加归档大小上限，也不缓冲整个文件。

每个活动导出最多增加 1 MiB JavaScript 工作空间，另有既有的最多 64 KiB 当前读取。未测量浏览器或文件系统内部缓冲。合并器复制数据但不修改来源别名；导出器继续擦除其独立拥有的来源副本。写入成功、失败及释放时擦除写缓冲。来源必须独立拥有，目标必须在写入承诺兑现前消费字节。

每次读取及每次刷新前后检查取消。每个文件关闭和大小验证前会刷新尾部不足一批的数据；取消时丢弃尚未写出的字节。仅文件系统写入成功后增加已写进度，不把缓冲区中已读取的字节算入。失败写入在文件系统侧可能具有未知的部分效果，因此不会计数或宣称完成。既有的中止、未完成标记、身份检查及非递归清理保持不变；中止失败时仍禁止抢在可能存活的写入器之前删除文件。挂起的浏览器调用仍只能协作取消，不能强行打断。大小、哈希元数据及最终标记提交规则不变。

合成精确字节测试使用 2 MiB + 17 字节：33 次有界读取产生三次负载写入（1 MiB、1 MiB、17 字节），而非 33 次。测试覆盖两个导出器、写入失败、刷新前及写入中的取消、尾部数据、已写进度和来源别名保留。这些是操作计数，不是浏览器或磁盘耗时声明。
